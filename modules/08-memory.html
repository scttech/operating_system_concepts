Module 8

Memory Management

Programs must be in memory to run. The OS decides where, keeps processes out of each other's memory, and makes limited RAM feel large and private.

Logical vs. physical addresses

The CPU generates logical (virtual) addresses. The MMU translates each one into a physical address at run time. That indirection lets the OS relocate programs, enforce protection and share memory without the program noticing.

Contiguous allocation

The simplest scheme gives each process one contiguous block. When a request arrives, the OS must pick a free hole:

  • First-fit: first hole that is big enough (fast).
  • Best-fit: smallest hole that fits (leaves tiny leftover slivers).
  • Worst-fit: largest hole (leaves big leftovers, but destroys large holes).

Over time, free memory shatters into many small holes: external fragmentation. Compaction fixes it by sliding processes together, at the cost of copying and relocating them.

Paging

Paging splits the logical address space into fixed-size pages and physical memory into same-size frames. A page table maps each page to a frame, so a process's memory need not be contiguous. This removes external fragmentation; the cost is internal fragmentation in each process's last page (about half a page on average).

A logical address splits into two parts: page number (high bits, index into the page table) and offset (low bits, position inside the page). For a page size of 2n bytes, the offset is n bits. For example, a 32-bit address with 4 KiB pages has a 20-bit page number and 12-bit offset.

Why one big page table does not work

Take a 32-bit machine with 4 KiB pages. The page number has 20 bits, so a flat page table needs 220 = 1,048,576 entries. At 4 bytes each, that is 4 MiB for every process, even a tiny one that uses a few pages. A hundred processes would spend 400 MiB just on tables. With 64-bit addresses a flat table is impossible: a 48-bit address space would need 236 entries, which is 512 GiB per process.

Notice what is wasteful: most of a process's address space is empty. A typical process has a little code at the bottom, a heap above it, some libraries, and a stack at the very top, with huge gaps between them. We should not pay for table entries that describe nothing.

Multi-level page tables

A multi-level page table applies the paging idea to the page table itself. The page number is cut into pieces. The first piece indexes a small top-level table. Each entry points to a second-level table, and the second piece indexes that. Second-level tables are created only for regions the process actually uses. If a whole region is empty, its top-level entry is simply marked not present and no lower table exists.

The classic 32-bit x86 layout is 10 + 10 + 12 bits: 10 bits for the top-level index, 10 for the second-level index, and 12 for the offset within a 4 KiB page. Each table has 1,024 entries of 4 bytes, which is exactly one page, so the tables themselves can be stored in ordinary page-sized frames. For the address 0x00403004 the top-level index is 1, the second-level index is 3 and the offset is 4. A typical small process needs one top-level table and about three second-level tables: 16 KiB instead of 4 MiB.

On 64-bit x86 the layout is 9 + 9 + 9 + 9 + 12 bits (48-bit addresses): four levels of 512 entries, each table exactly one 4 KiB page of 8-byte entries.

The same idea in code

This tiny machine uses 16-bit addresses (4 + 4 + 8 bits) so every table fits on screen. Both versions print identical output, and the numbers in the comments line up in both tabs: (1) a second-level table is created only when needed; (2)–(5) split the address with shifts and masks; (6) a missing table means a page fault; (7) the frame number is placed in front of the unchanged offset.

Why C is the clearer version here: a page table is a block of fixed-size entries in memory that the hardware reads directly. C shows that honestly: arrays of fixed-size structs, pointers for the next level, and explicit bit masks. A real entry is a packed machine word with flag bits next to the frame number; here each entry is just a frame number to keep the idea visible.

/* Two-level address translation for a tiny machine: 16-bit addresses = 4 + 4 + 8 bits. */
#include <stdio.h>
#include <stdint.h>

#define OFFSET_BITS 8
#define INDEX_BITS  4
#define ENTRIES     (1u << INDEX_BITS)
#define NOT_PRESENT (-1)

typedef struct { int frame[ENTRIES]; } leaf_t;      /* second level: page number -> frame number */
typedef struct { leaf_t *leaf[ENTRIES]; } root_t;   /* top level: pointer to a second-level table, or NULL */

static root_t root;                                 /* all pointers start out NULL */
static leaf_t pool[3];                              /* memory for the second-level tables we will need */
static int pool_used = 0;

static void map_page(unsigned vpn, int frame) {
    unsigned top = vpn >> INDEX_BITS, low = vpn & (ENTRIES - 1);
    if (root.leaf[top] == NULL) {                   /* (1) a second-level table is created only when first needed */
        root.leaf[top] = &pool[pool_used++];
        for (unsigned i = 0; i < ENTRIES; i++) root.leaf[top]->frame[i] = NOT_PRESENT;
    }
    root.leaf[top]->frame[low] = frame;
}

/* Returns 0 on success; 1 = no top-level entry; 2 = page not present in an existing table. */
static int translate(unsigned vaddr, unsigned *paddr) {
    unsigned offset = vaddr & ((1u << OFFSET_BITS) - 1);   /* (2) the low bits are the offset within the page */
    unsigned vpn = vaddr >> OFFSET_BITS;                   /* (3) everything above is the virtual page number */
    unsigned top = vpn >> INDEX_BITS;                      /* (4) its high bits pick the top-level entry... */
    unsigned low = vpn & (ENTRIES - 1);                    /* (5) ...and its low bits pick the entry in that table */
    leaf_t *leaf = root.leaf[top];
    if (leaf == NULL) return 1;                            /* (6) NULL pointer = "not present" at the top level */
    int frame = leaf->frame[low];
    if (frame == NOT_PRESENT) return 2;
    *paddr = ((unsigned)frame << OFFSET_BITS) | offset;    /* (7) frame number in front of the unchanged offset */
    return 0;
}

int main(void) {
    for (unsigned i = 0; i < 4; i++) map_page(0x00 + i, (int)(5 + 7 * i));    /* code  */
    for (unsigned i = 0; i < 3; i++) map_page(0x10 + i, (int)(5 + 7 * (4 + i)));  /* heap  */
    for (unsigned i = 0; i < 2; i++) map_page(0xFE + i, (int)(5 + 7 * (7 + i)));  /* stack */

    const unsigned addresses[] = { 0x0012, 0x03FF, 0x1034, 0xFE80, 0x5000, 0x0412 };
    for (unsigned k = 0; k < sizeof addresses / sizeof addresses[0]; k++) {
        unsigned a = addresses[k], vpn = a >> OFFSET_BITS, paddr = 0;
        unsigned top = vpn >> INDEX_BITS, low = vpn & (ENTRIES - 1);
        int rc = translate(a, &paddr);
        printf("0x%04X -> top %2u, second %2u, offset 0x%02X -> ", a, top, low, a & 0xFFu);
        if (rc == 0) printf("frame %2d -> physical 0x%04X\n", (int)(paddr >> OFFSET_BITS), paddr);
        else printf("PAGE FAULT (%s)\n", rc == 1 ? "no second-level table" : "page not present");
    }
    printf("second-level tables allocated: %d; entries used: %u instead of %u for one flat table\n",
           pool_used, ENTRIES + pool_used * ENTRIES, 1u << (2 * INDEX_BITS));
    return 0;
}

Python is fine for the logic, but it hides the hardware reality. Lists and None play the roles of arrays and the “not present” marker, and Python decides how big each entry is, so it is a little contrived as a model of a real page table. The shifts, masks and the two-step lookup are exactly the same, which is why every numbered comment matches the C tab.

"""Two-level address translation for a tiny machine: 16-bit addresses = 4 + 4 + 8 bits."""

OFFSET_BITS = 8
INDEX_BITS = 4
ENTRIES = 1 << INDEX_BITS

root = [None] * ENTRIES                 # top level: a second-level table (a list), or None
tables_created = 0


def map_page(vpn, frame):
    global tables_created
    top, low = vpn >> INDEX_BITS, vpn & (ENTRIES - 1)
    if root[top] is None:               # (1) a second-level table is created only when first needed
        root[top] = [None] * ENTRIES
        tables_created += 1
    root[top][low] = frame


def translate(vaddr):
    """Returns (physical address, None) or (None, reason for the fault)."""
    offset = vaddr & ((1 << OFFSET_BITS) - 1)   # (2) the low bits are the offset within the page
    vpn = vaddr >> OFFSET_BITS                  # (3) everything above is the virtual page number
    top = vpn >> INDEX_BITS                     # (4) its high bits pick the top-level entry...
    low = vpn & (ENTRIES - 1)                   # (5) ...and its low bits pick the entry in that table
    leaf = root[top]
    if leaf is None:                            # (6) None = "not present" at the top level
        return None, "no second-level table"
    frame = leaf[low]
    if frame is None:
        return None, "page not present"
    return (frame << OFFSET_BITS) | offset, None    # (7) frame number in front of the unchanged offset


for i in range(4):
    map_page(0x00 + i, 5 + 7 * i)               # code
for i in range(3):
    map_page(0x10 + i, 5 + 7 * (4 + i))         # heap
for i in range(2):
    map_page(0xFE + i, 5 + 7 * (7 + i))         # stack

for a in (0x0012, 0x03FF, 0x1034, 0xFE80, 0x5000, 0x0412):
    vpn = a >> OFFSET_BITS
    print(f"0x{a:04X} -> top {vpn >> INDEX_BITS:2d}, second {vpn & (ENTRIES - 1):2d}, offset 0x{a & 0xFF:02X} -> ", end="")
    paddr, why = translate(a)
    if why is None:
        print(f"frame {paddr >> OFFSET_BITS:2d} -> physical 0x{paddr:04X}")
    else:
        print(f"PAGE FAULT ({why})")
print(f"second-level tables allocated: {tables_created}; "
      f"entries used: {ENTRIES + tables_created * ENTRIES} instead of {1 << (2 * INDEX_BITS)} for one flat table")

Expected output (identical in C and Python): addresses in the code, heap and stack translate; 0x5000 faults because its top-level entry has no second-level table; 0x0412 faults because its second-level table exists but that page is not mapped. The last line shows 64 entries used instead of 256.

What is in a page-table entry?

Each entry holds the frame number and a few flag bits that the hardware checks on every access. A page-table entry (PTE) on x86 includes:

FlagMeaningUsed for
PresentThe page is in a frame right nowDemand paging: a clear bit raises a page fault
Read/writeWrites are allowedProtecting code and shared data; copy-on-write starts read-only
User/supervisorUser-mode code may access itKeeping the kernel's memory away from programs (kernel and user mode)
AccessedThe page was read or written recentlyThe reference bit for page replacement (Clock)
DirtyThe page was written since it was loadedKnowing whether it must be saved before eviction
No-executeInstructions may not run from this pageStopping injected data from running as code (security)

Making translation fast: the TLB

A multi-level table saves memory but makes a translation slower: every level is another memory read. Reading a table in memory in order to translate an address is called a page walk. With four levels, one memory access could become five. Programs would crawl, were it not for the TLB, a small hardware cache of recent translations. A hit skips the walk completely. A miss walks the tables and then caches the result. With TLB hit ratio h, n table levels, TLB lookup time tTLB and memory time tmem:

EAT = h × (tTLB + tmem) + (1 − h) × (tTLB + n × tmem + tmem)

With a 1 ns TLB, 100 ns memory and a 98% hit ratio, a single-level table gives EAT = 0.98 × 101 + 0.02 × 201 = 103 ns. With two levels it is 105 ns, and with four levels 109 ns. Even with deep tables the cost stays under 10%, as long as the hit ratio is high. It is high because programs show locality of reference: they keep reusing a small set of pages. The TLB reach (entries × page size) is how much memory the TLB can cover at once: 64 entries of 4 KiB cover only 256 KiB.

AdvancedGoing deeper: how real hardware does it
  • Page-walk caches. CPUs also cache the upper-level entries, so a TLB miss often needs only one or two memory reads, not n. The EAT formula above is the worst case.
  • Address-space identifiers. Each process has its own page tables, so after a context switch the old TLB entries are wrong. Without help the OS must flush the TLB on every switch, so the new process starts with a cold TLB. An ASID (x86 calls it PCID) tags each entry with its process, so entries from several processes can live together and no flush is needed.
  • Huge pages. A huge page of 2 MiB (or 1 GiB) skips the last table level, because the offset grows to 21 bits (or 30). One TLB entry then maps 512× (or 262,144×) more memory, which greatly extends the TLB reach for databases and virtual machines. The cost is internal fragmentation and needing a large contiguous run of frames. Linux can create them automatically (“transparent huge pages”).
  • More levels. Newer x86 CPUs support five levels (57-bit addresses) for machines with more than 256 TiB of address space. RISC-V defines Sv39, Sv48 and Sv57 (3, 4 and 5 levels); ARM supports 4 KiB, 16 KiB and 64 KiB page sizes with different level splits. More levels mean longer walks.
  • Virtual machines pay twice. A guest OS has its own page tables, and the hypervisor translates guest “physical” addresses again (nested or extended page tables). With 4 levels each, one TLB miss can need up to (4 + 1) × (4 + 1) − 1 = 24 memory reads, which is why hypervisors rely on huge pages and large TLBs.
  • Security trade-offs. After the Meltdown vulnerability, kernels such as Linux began switching to a separate set of page tables on every entry to the kernel (page-table isolation). That made context and mode switches more expensive and made ASIDs more valuable.
  • Software-managed TLBs. Some architectures (for example MIPS) leave TLB misses to the OS, which then walks any data structure it likes. Others, like x86 and ARM, walk the tables in hardware, so the table format is fixed by the CPU.

Other designs

  • Hashed and inverted page tables have one entry per physical frame (or hash bucket) instead of per virtual page, trading lookup time for table size. They suit very large address spaces.
  • Segmentation divides memory by logical units (code, stack, heap). Modern systems mostly use paging, sometimes with segment-like protection.
