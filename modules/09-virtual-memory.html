Virtual Memory

Virtual memory separates what a program thinks it has (a huge private address space) from the RAM that actually exists. Only the pages in active use need to be resident.

Demand paging

With demand paging a page is loaded only when first referenced. Each page-table entry has a valid bit. When the CPU touches an invalid page, a page fault traps to the OS:

  1. Check that the reference is legal (otherwise: segmentation fault).
  2. Find a free frame. If none, choose a victim with a replacement algorithm (writing it out first if its dirty bit is set).
  3. Schedule a disk read for the needed page; the process blocks meanwhile.
  4. Update the page table and TLB, then restart the faulting instruction.

This works because of locality of reference: programs reuse nearby and recently used memory, so faults are rare.

Try it: watch pages being assigned

Why C is the clearer version here: mmap reserves addresses and getrusage reports how many minor page faults this process has taken, so the program shows demand paging directly. The numbers are not printed, because they differ between systems; the program prints only the comparison the lesson is about.

/* Demand paging you can measure: memory is not assigned until a page is first touched. Linux or macOS. */
#define _POSIX_C_SOURCE 200809L
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <unistd.h>

#define PAGES 256

static long minor_faults(void) {
    struct rusage usage;
    getrusage(RUSAGE_SELF, &usage);
    return usage.ru_minflt;                         /* page faults served without reading from disk */
}

int main(void) {
    long page = sysconf(_SC_PAGESIZE);
    /* (1) mmap reserves addresses for 256 pages. No physical memory is assigned yet. */
    char *region = mmap(NULL, (size_t)(PAGES * page), PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (region == MAP_FAILED) return 1;
    printf("mapped %d pages: no physical memory is assigned until a page is first touched\n", PAGES);

    long before = minor_faults();
    for (long i = 0; i < PAGES; i++) region[i * page] = 1;      /* (2) first touch of each page: a page fault, and the kernel supplies a zeroed frame */
    long first_pass = minor_faults() - before;
    printf("touching each page for the first time caused page faults: %s\n", first_pass >= 8 ? "True" : "False");

    before = minor_faults();
    for (long i = 0; i < PAGES; i++) region[i * page] = 2;      /* (3) the pages are now mapped: touching them again needs no fault */
    long second_pass = minor_faults() - before;
    printf("touching them all a second time caused far fewer: %s\n", second_pass * 4 < first_pass ? "True" : "False");
    munmap(region, (size_t)(PAGES * page));
    return 0;
}

Python has the same two calls (mmap and resource.getrusage), so it is not contrived, but it is the only way to see this in Python. An ordinary Python list lives inside memory the interpreter manages, so you cannot tell when the kernel assigned each page. Needs Linux or macOS.

"""Demand paging you can measure: memory is not assigned until a page is first touched. Linux or macOS."""
import mmap
import resource

PAGES = 256
page = mmap.PAGESIZE


def minor_faults():
    return resource.getrusage(resource.RUSAGE_SELF).ru_minflt      # page faults served without reading from disk


region = mmap.mmap(-1, PAGES * page, flags=mmap.MAP_PRIVATE)                             # (1) reserves addresses for 256 pages. No physical memory is assigned yet.
print(f"mapped {PAGES} pages: no physical memory is assigned until a page is first touched")

before = minor_faults()
for i in range(PAGES):
    region[i * page] = 1                                           # (2) first touch of each page: a page fault, and the kernel supplies a zeroed frame
first_pass = minor_faults() - before
print(f"touching each page for the first time caused page faults: {first_pass >= 8}")

before = minor_faults()
for i in range(PAGES):
    region[i * page] = 2                                           # (3) the pages are now mapped: touching them again needs no fault
second_pass = minor_faults() - before
print(f"touching them all a second time caused far fewer: {second_pass * 4 < first_pass}")
region.close()

Effective access time

If memory takes tm and a page fault costs tf (milliseconds for a disk, so about 100,000× slower), then EAT = (1 − p) × tm + p × tf. A fault rate of 1 in 1000 on a 100 ns memory with an 8 ms fault already slows the system 81×.

Thrashing and the working set

If a process doesn't have enough frames for its current locality, it faults constantly, and the CPU sits idle waiting for the disk. The OS then (wrongly) adds more processes and makes it worse: thrashing. The cure is the working-set model (give each process the pages it has used in the last Δ references) or page-fault-frequency control, combined with suspending some processes when memory is overcommitted.

Other virtual-memory ideas

  • Swapping moves whole processes (or, in modern systems, individual pages) between RAM and the backing store on disk.
  • Copy-on-write makes fork() cheap by sharing pages until someone writes.
  • Memory-mapped files let you access file data through ordinary loads and stores.
  • Prepaging, huge pages and NUMA policies are performance refinements on the same foundation.

AdvancedGoing deeper: what the kernel does on a page fault
  • Three kinds of fault. A minor fault maps a page that is already in memory (a zero page, or a page cached by another process). A major fault must read from disk. An invalid fault touches an address that is not mapped at all and ends in SIGSEGV.
  • Approximating LRU. True LRU would need a timestamp on every memory access. Hardware instead sets an accessed bit in the page-table entry, and the OS scans pages with the clock algorithm. Linux keeps active and inactive lists, and a page must be touched while inactive to earn promotion.
  • Memory-mapped files and the page cache. read() usually copies from the kernel’s page cache, and mmap maps those same pages into the process. File data and program memory compete for the same frames, which is why free memory on a busy Linux machine looks low yet is mostly reclaimable cache.
  • Swap, zswap and the OOM killer. When memory is short, anonymous pages go to swap (or are compressed in RAM with zswap). If reclaim fails, Linux’s out-of-memory killer picks a process to terminate. Mobile systems skip swap and kill background apps instead.
  • Overcommit. Linux will happily promise more memory than exists, relying on the fact that most pages are never touched. The page-fault example above is why this works, and also why a program can be killed long after malloc said yes.
  • Prefetching and Belady’s anomaly. The OS reads ahead when it sees sequential access. And FIFO can produce more faults with more frames (Belady’s anomaly), while stack algorithms such as LRU cannot.
