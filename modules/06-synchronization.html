Process Synchronization

When concurrent threads or processes share data, the result can depend on exact timing. Synchronization tools enforce order and exclusive access.

The race condition

A race condition exists when the outcome depends on how operations interleave. Even counter++ is three machine steps (load, add, store), so two threads can both load the same old value and one increment disappears.

Step the threads by hand: run thread 1's LOAD, then thread 2's LOAD, then everything else. Then switch on the mutex and notice that thread 2 is forced to wait.

The critical-section problem

The code that touches shared data is the critical section. A correct solution must provide:

  1. Mutual exclusion: only one thread inside at a time.
  2. Progress: if no one is inside, a thread that wants in is not delayed forever by threads that don't.
  3. Bounded waiting: a limit on how often others can overtake a waiting thread.
do {
    acquire(lock);      // entry section
    /* critical section: touch shared data */
    release(lock);      // exit section
    /* remainder section */
} while (true);

Bounded buffer (producer–consumer)

Producers add items to a buffer of N slots and consumers remove them. Three semaphores solve it: empty = N (free slots), full = 0 (filled slots) and mutex = 1 (protects the buffer structure).

producer:                     consumer:
  wait(empty)                   wait(full)
  wait(mutex)                   wait(mutex)
  insert item                   remove item
  signal(mutex)                 signal(mutex)
  signal(full)                  signal(empty)

Order matters: if a producer does wait(mutex) before wait(empty) and the buffer is full, it sleeps while holding the mutex, so the consumer can never get in to make room. That is a deadlock. See Module 7.

Other classic problems

  • Readers–writers: many readers may share data, but writers need exclusive access (beware writer starvation).
  • Dining philosophers: see Module 7.
  • Priority inversion: a high-priority task blocked on a lock held by a low-priority task that is preempted by a medium one. Fix with priority inheritance.
