Lab 1

Processes: launching, waiting and forking

Use Python to create and manage processes the way a shell does. You will see process IDs, exit codes, inherited environments and parallel children. On Linux or macOS you will also use fork, exec and wait directly and catch a zombie.

About 45 minutesPart A: any systemPart B: Linux, macOS, WSL or CodioRelated: Module 3 Processes, Module 4 CPU Scheduling

What you will practice

  • Reading a process's id and its parent's id.
  • Starting a child process, waiting for it, and reading its exit code.
  • Seeing that a child inherits its parent's environment.
  • Running several children at once and measuring the difference from running them one after another.
  • Using fork, exec and wait, and recognizing a zombie process.

Part A: launching processes (any system)

Predict first: if you start four children that each sleep for half a second, how long will your program take if they run one after another? If they run at the same time?

"""Lab 1a - Processes: inspect and launch them from Python (Windows, macOS and Linux)."""
import os
import subprocess
import sys
import time

# (1) Every process has an id, and a parent that created it.
print(f"this process: pid={os.getpid()}  parent pid={os.getppid()}")

# (2) Start a child program and wait for it to finish (like fork + exec + wait).
child = subprocess.run(
    [sys.executable, "-c", "import os; print('hello from child, pid', os.getpid())"],
    capture_output=True, text=True)
print(f"child said:     {child.stdout.strip()}")
print(f"child exit code: {child.returncode}")

# (3) A child reports success or failure through its exit code.
failing = subprocess.run([sys.executable, "-c", "raise SystemExit(3)"])
print(f"a failing child exits with code {failing.returncode}")

# (4) A child inherits a copy of its parent's environment (part of the PCB).
env = {**os.environ, "LAB_GREETING": "inherited!"}
shown = subprocess.run([sys.executable, "-c", "import os; print(os.environ['LAB_GREETING'])"],
                       env=env, capture_output=True, text=True)
print(f"child saw LAB_GREETING = {shown.stdout.strip()}")

# (5) Popen starts a child WITHOUT waiting, so several can run at the same time.
start = time.perf_counter()
kids = [subprocess.Popen([sys.executable, "-c", "import time; time.sleep(0.5)"]) for _ in range(4)]
print(f"started {len(kids)} children; all have different pids: {len({k.pid for k in kids}) == 4}")
for kid in kids:
    kid.wait()                      # collect each child's exit status
elapsed = time.perf_counter() - start
print(f"4 children that each sleep 0.5 s finished in {elapsed:.1f} s "
      f"({'in parallel' if elapsed < 1.6 else 'one after another'}; sequential would take 2.0 s or more)")

What to notice

  1. (1) Your own program is a process with a parent. The parent is whatever started it: your terminal, shell or editor.
  2. (2) subprocess.run starts a child and waits, like the shell does after fork and exec. The exit code 0 means success by convention.
  3. (3) Any non-zero exit code means failure, and the parent can read it. This is how scripts and build tools know a step failed.
  4. (4) The child received a copy of the parent's environment variables. Changing the copy would not change the parent's. This inheritance is part of what the kernel's process control block records.
  5. (5) Popen starts a child without waiting, so the four sleepers overlap and the total is about 0.5 s, not 2 s. Sleeping children use almost no CPU, which is why running more of them than you have cores still works.

Part B: fork, exec and wait (Linux, macOS, WSL or Codio)

Windows has no os.fork(), so the script exits with a message there. Run Part B in WSL, in Codio, or on a Linux or macOS computer. Predict first: the program calls fork() three times in a row. How many processes exist at the end? (Check the fork tree in Module 3.)

C is the natural language for this part. fork, exec and wait are C library functions, and Python's os.fork is a thin wrapper around them. Build and run it with gcc -std=c99 -D_POSIX_C_SOURCE=200809L -o lab1_fork lab1_fork.c && ./lab1_fork on Linux, macOS, WSL or Codio. The output is identical to the Python version.

/* Lab 1b (C) - fork, exec and wait. Linux, macOS, WSL or Codio: Windows has no fork(). */
#define _POSIX_C_SOURCE 200809L
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void) {
    /* Flush every print immediately. fork() copies the process INCLUDING its unflushed output buffer,
       so buffered text could be printed twice, or in a surprising order when output goes to a pipe or file. */
    setvbuf(stdout, NULL, _IONBF, 0);

    /* (1) fork() is called once but returns twice: 0 in the child, the child's pid in the parent. */
    pid_t pid = fork();
    if (pid == 0) {
        printf("child : fork() returned 0\n");
        _exit(7);                                   /* leave immediately; 7 becomes the exit status */
    }
    int status = 0;
    waitpid(pid, &status, 0);                       /* (2) the parent waits, then reads the child's exit status */
    printf("parent: fork() returned the child's pid (a positive number: %s)\n", pid > 0 ? "True" : "False");
    printf("parent: the child exited with code %d\n", WEXITSTATUS(status));

    /* (3) exec replaces the child's program. This is how a shell runs "echo". */
    pid = fork();
    if (pid == 0) {
        execlp("echo", "echo", "this line was printed by the echo program", (char *)NULL);
        _exit(127);                                 /* only reached if exec failed */
    }
    waitpid(pid, NULL, 0);

    /* (4) Every fork doubles the number of processes. Each process records itself in a file. */
    char path[64];
    snprintf(path, sizeof path, "/tmp/lab1_forks_%d.txt", (int)getpid());
    FILE *log = fopen(path, "w");
    if (log) fclose(log);
    pid_t root = getpid();
    for (int i = 0; i < 3; i++) fork();
    log = fopen(path, "a");
    if (log) { fprintf(log, "%d\n", (int)getpid()); fclose(log); }
    while (wait(NULL) > 0) { }                      /* wait for our own children (the grandchildren wait for theirs) */
    if (getpid() != root) _exit(0);
    int lines = 0, ch;
    log = fopen(path, "r");
    while (log && (ch = fgetc(log)) != EOF) if (ch == '\n') lines++;
    if (log) fclose(log);
    printf("3 forks in a row produced %d processes\n", lines);
    remove(path);

    /* (5) A zombie: a child that has exited but has not been waited for yet. */
    pid = fork();
    if (pid == 0) _exit(0);
    struct timespec pause = { 0, 200 * 1000 * 1000 };
    nanosleep(&pause, NULL);                        /* give the child time to exit */
    char cmd[64], state[16] = "";
    snprintf(cmd, sizeof cmd, "ps -o stat= -p %d 2>/dev/null", (int)pid);
    FILE *ps = popen(cmd, "r");
    if (ps) {
        if (fgets(state, sizeof state, ps)) state[strcspn(state, " \n")] = '\0';
        pclose(ps);
    }
    if (state[0]) printf("before wait(): ps shows the child's state as '%s' (Z means zombie)\n", state);
    waitpid(pid, NULL, 0);                          /* reaping removes the zombie */
    printf("after wait(): the zombie is gone\n");
    return 0;
}

Python's os.fork, os.execvp and os.waitpid make the same system calls, so the behavior and the output are identical to the C tab. os._exit (like C's _exit) ends the child without Python's normal cleanup, which is what you want right after fork.

"""Lab 1b - fork, exec and wait (Linux, macOS, WSL or Codio: Windows has no os.fork)."""
import functools
import os
import shutil
import subprocess
import sys
import tempfile
import time

# Flush every print immediately. fork() copies the process INCLUDING its unflushed output buffer,
# so buffered text could be printed twice, or in a surprising order when output goes to a pipe or file.
print = functools.partial(print, flush=True)

if not hasattr(os, "fork"):
    sys.exit("os.fork() is not available here. Run this lab on Linux, macOS, WSL or Codio.")

# (1) fork() is called once but returns twice: 0 in the child, the child's pid in the parent.
pid = os.fork()
if pid == 0:
    print("child : fork() returned 0")
    os._exit(7)                     # leave immediately; 7 becomes the exit status
_, status = os.waitpid(pid, 0)      # (2) the parent waits, then reads the child's exit status
print(f"parent: fork() returned the child's pid (a positive number: {pid > 0})")
print(f"parent: the child exited with code {os.WEXITSTATUS(status)}")

# (3) exec replaces the child's program. This is how a shell runs "echo".
pid = os.fork()
if pid == 0:
    os.execvp("echo", ["echo", "this line was printed by the echo program"])
os.waitpid(pid, 0)

# (4) Every fork doubles the number of processes. Each process records itself in a file.
path = os.path.join(tempfile.gettempdir(), f"lab1_forks_{os.getpid()}.txt")
open(path, "w").close()
root = os.getpid()
for _ in range(3):
    os.fork()
with open(path, "a") as log:
    log.write(f"{os.getpid()}\n")
try:
    while True:
        os.wait()                   # wait for our own children (the grandchildren wait for theirs)
except ChildProcessError:
    pass
if os.getpid() != root:
    os._exit(0)
print(f"3 forks in a row produced {len(open(path).read().split())} processes")
os.remove(path)

# (5) A zombie: a child that has exited but has not been waited for yet.
pid = os.fork()
if pid == 0:
    os._exit(0)
if shutil.which("ps"):
    time.sleep(0.2)                 # give the child time to exit
    state = subprocess.run(["ps", "-o", "stat=", "-p", str(pid)], capture_output=True, text=True).stdout.strip()
    print(f"before wait(): ps shows the child's state as '{state}' (Z means zombie)")
os.waitpid(pid, 0)                  # reaping removes the zombie
print("after wait(): the zombie is gone")

What to notice

  1. (1) fork() is called once but returns twice: 0 in the new child and the child's pid in the parent. That is how the same code tells the two apart.
  2. (2) waitpid blocks the parent until the child ends, then returns its exit status. Without it you get a zombie (see (5)).
  3. (3) exec does not create a process. It replaces the current program with another one in the same process. A shell runs a command with fork then exec in the child and wait in the parent.
  4. (4) Three forks in a row make 23 = 8 processes, because every process that exists runs the next fork() too.
  5. (5) A finished child stays in the process table as a zombie (state Z) until its parent collects its exit status. Zombies use almost no memory but they do use a process-table slot.
  6. Why the script flushes every print: fork copies the process, including text waiting in its output buffer. Without flushing, that text can be printed twice or out of order, especially when output goes to a file or pipe.

Common mistakes

  • Forgetting to wait. Children become zombies and you never see their exit codes.
  • Forgetting that both processes run the code after fork(). Use if pid == 0 to separate them, and make the child exit so it does not continue into the parent's code.
  • Calling fork in a program that already uses threads. Only the calling thread exists in the child, which can leave locks permanently held. Prefer subprocess or multiprocessing in threaded programs.
  • Running Part B on Windows. There is no os.fork there. Use WSL, Codio or a Linux or macOS machine.
