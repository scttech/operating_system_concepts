Lab 3

Exploring system resources with Python

Ask the operating system what it knows about your computer: CPU use, memory, swap, disk space and the processes that are running. Then explain what each number means in terms of the concepts from the lessons.

About 40 minutesAny systemNeeds the psutil packageRelated: Module 4, Module 8, Module 9, Module 10

What you will practice

  • Using the standard library (os, platform, shutil) for basic system facts.
  • Using psutil to read CPU, memory, swap and process information.
  • Telling apart free and available memory, logical and physical cores, and resident and virtual memory.
  • Handling processes you are not allowed to inspect, or that disappear while you look.

Setup

python -m pip install psutil

On Windows you can use py -m pip install psutil. On Codio it may already be installed. If it is missing the script still prints the standard-library facts and tells you what to install.

The script

Predict first: before running it, estimate how much RAM your computer has, how much is in use, and which program uses the most memory. Then compare.

"""Lab 3 - Exploring system resources with Python (standard library first, then psutil)."""
import os
import platform
import shutil
import sys
import time

try:
    import psutil                   # install with:  python -m pip install psutil
except ImportError:
    psutil = None

print("== The basics (standard library only) ==")
print(f"operating system: {platform.system()} {platform.release()}")
print(f"logical CPUs:     {os.cpu_count()}")
total, used, free = shutil.disk_usage(os.path.abspath(os.sep))
print(f"disk:             {used / 2**30:.0f} GiB used of {total / 2**30:.0f} GiB ({used / total:.0%})")

if psutil is None:
    print("\npsutil is not installed. Run:  python -m pip install psutil   then run this lab again.")
    sys.exit(0)

print("\n== CPU ==")
print(f"physical cores: {psutil.cpu_count(logical=False)}   logical cores: {psutil.cpu_count()}")
busy = psutil.cpu_percent(interval=1, percpu=True)          # (1) measured over 1 second
print(f"busy % per logical core over 1 s: {busy}")

print("\n== Memory ==")
ram, swap = psutil.virtual_memory(), psutil.swap_memory()
print(f"RAM:  {ram.total / 2**30:.1f} GiB total, {ram.available / 2**30:.1f} GiB available ({ram.percent}% in use)")
print(f"swap: {swap.total / 2**30:.1f} GiB total ({swap.percent}% in use)")

print("\n== Processes ==")
rows = []
for proc in psutil.process_iter(["pid", "name", "memory_info", "num_threads", "status"]):   # (2)
    info = proc.info
    if info["memory_info"]:         # None when the OS refuses access: always handle that case
        rows.append((info["memory_info"].rss, info["pid"], info["name"] or "?", info["num_threads"], info["status"]))
rows.sort(reverse=True)
print(f"{len(rows)} processes visible. Top 5 by resident memory (RSS):")
for rss, pid, name, threads, status in rows[:5]:
    print(f"  pid {pid:>6}  {name[:24]:<24} {rss / 2**20:8.1f} MiB  {threads:>3} threads  {status}")

print("\n== This process ==")
me = psutil.Process()                                       # (3) no argument means "myself"
print(f"pid {me.pid}, {me.num_threads()} thread(s), started at {time.strftime('%H:%M:%S', time.localtime(me.create_time()))}")
print("ancestors:", " <- ".join(f"{p.name()}({p.pid})" for p in [me, *me.parents()]))   # (4) parent, grandparent, ...

Run it with python lab3_resources.py.

What to notice

  1. Logical versus physical cores. A hardware thread (hyper-threading) lets one physical core look like two logical CPUs to the scheduler. The scheduler in Module 4 schedules onto logical CPUs.
  2. (1) cpu_percent(interval=1) measures busy time over a period. Calling it without an interval returns a meaningless first value because there is nothing to compare against.
  3. Available is not free. Free memory is memory nobody is using at all. Available also counts memory the OS can take back instantly, such as disk cache. A healthy system often has almost no free memory: the OS uses spare RAM as a cache (see Module 9).
  4. Swap is the backing store for virtual memory. Heavy swap use together with a busy disk is a sign of thrashing.
  5. (2) process_iter with a list of attributes fetches them efficiently, and it returns None for any value the OS refuses to show. Checking for None prevents crashes on protected processes.
  6. RSS (resident set size) is the memory a process currently has in RAM. It is not the same as its virtual size, which includes memory that is mapped but not loaded.
  7. (3) and (4) psutil.Process() with no argument means “this process”, and parents() walks up the process tree you built in Lab 1, all the way to init/systemd or the system's first process.

Try it

  1. Run the script, then open a few big programs (a browser with many tabs) and run it again. Which numbers changed the most?
  2. Add a sample of CPU use for the whole system every second for ten seconds. Start something heavy halfway through and watch the numbers.
  3. List the five processes with the most threads. Is it the same list as the top memory users?
  4. Print how many processes have each status (running, sleeping, and so on) using collections.Counter. Do you ever see a zombie? Where would you expect one (see Lab 1)?
  5. Use psutil.disk_io_counters() or psutil.net_io_counters() before and after downloading a large file. What is the difference?

Common mistakes

  • Reading cpu_percent() once with no interval. The first call is not meaningful.
  • Treating “free” as “available”. A system with 200 MB free may have gigabytes available.
  • Not handling AccessDenied and NoSuchProcess. Processes can vanish between listing them and reading their details, and some are protected.
  • Assuming every field exists on every OS. Some values (such as load average) are missing or different on Windows or macOS.

Reflection questions (good journal entries)

  1. Your computer shows 95% of RAM “in use” but runs smoothly. Using the idea of the page cache, explain how that can be normal. What numbers would make you worried instead?
  2. Pick the process using the most memory. Explain, using RSS and virtual memory, what that number does and does not tell you.
  3. Which resource (CPU, memory, disk) was the busiest on your machine, and what evidence from the script shows it?
