Hands-on with Docker

Small, self-guided labs that let you observe operating-system ideas on your own computer, using Docker. You read about kernels, processes and resource limits in the lessons. Here you see them happen.

This section is optional. Nothing else on the site depends on it, and if you skip it you lose nothing. It is meant for people learning on their own, at home, with no instructor or lab computers.

The big idea. A container is not a separate operating system. Containers share the kernel of the computer they run on, and differ only in user space: files, libraries, a package manager. On Windows and macOS, Docker Desktop runs a hidden Linux virtual machine, and every Linux container shares that machine's kernel. Lab 0 proves it in a few minutes. The later labs then use that shared Linux kernel as a real, observable operating system.

The labs

Do them in order, or jump to one that interests you: after Lab 0 each lab stands on its own unless it says otherwise.

    How each lab works

    1. Read the goal and the “Concept link” to the matching lesson on this site.
    2. Run each step and compare with the example output. The example output was captured from a real run, on the computer named in the lab, but your numbers, IDs and times will differ. Look for the pattern.
    3. Read “Why this matters” under each step: it ties what you just saw to the operating-system concept.
    4. Try it yourself, answer the knowledge checks (answers appear when you click), and run the Clean up step.

    Conventions used in every lab

    • Containers are named oslab-<lab number>-<purpose> and carry the label oslab=true, so everything from this guide can be removed with one command (below).
    • Throwaway containers use --rm, so they delete themselves.
    • Image versions are pinned (for example alpine:3.22, not latest) so the labs keep behaving the same way. Tags may need updating over time; the one exception is hello-world, Docker's own install check.
    • Commands that need an extra permission (--cap-add, --pid=host) are marked and explained. Nothing uses --privileged, and no lab mounts your home folder or any system folder into a container.
    • Use these labs on your own computer, with disposable containers. They are not a guide to securing production systems.

    Shell notes

    Commands are written to work unchanged in bash, zsh and PowerShell. They put a single-quoted command after sh -c and avoid double quotes inside it, because older Windows PowerShell (5.1) removes double quotes from arguments it passes to programs. Where a command truly differs between shells, both versions are shown. The troubleshooting page has more.

    Clean up everything from this guide

    This removes every container, image, volume and network that these labs created (they all carry the oslab label). It does not touch anything else on your computer. Remove containers first, because images in use cannot be removed.

    bash or zsh (macOS, Linux, WSL):

    docker rm -f $(docker ps -aq --filter label=oslab=true)
docker rmi -f $(docker images -q --filter label=oslab=true)
docker volume prune -a -f --filter label=oslab=true
docker network prune -f --filter label=oslab=true

    PowerShell:

    docker ps -aq --filter label=oslab=true | ForEach-Object { docker rm -f $_ }
docker images -q --filter label=oslab=true | ForEach-Object { docker rmi -f $_ }
docker volume prune -a -f --filter label=oslab=true
docker network prune -f --filter label=oslab=true

    If nothing is left to remove, docker rm and docker rmi print a usage message. That is fine.

    The distribution images the labs download (Debian, Ubuntu, Alpine, Fedora, Arch, the Python image and hello-world) are not labelled, because you did not build them. To remove them too and free the space:

    docker rmi debian:13-slim ubuntu:24.04 alpine:3.22 fedora:43 archlinux:base python:3.12-slim hello-world

    (It is safe if some are missing or still in use elsewhere: Docker tells you and skips them.) To see how much space Docker uses overall, run docker system df.
